Private multiplayer, 31 October 2026. The immediate next implementation from the delivery plan is now an unfunded private relay room, separate from local practice. Two browser clients connect to the Node service over WebSocket. The server creates random room and session credentials, owns ready countdown, fixed 20 Hz ticks, command order, combat, spending and results. The client never imports step or command and only renders authorized snapshots. Each connection is bound to one seat. Origin checks, strict bounded protocol messages, 2048 byte frame limits, a 60 message per second connection limit, room and connection caps, a ten second anonymous connection timeout and bounded outbound buffering are implemented. No wallet identity, funded room or public service is claimed.

SQLite checkpoints and command acknowledgments use synchronous FULL transactions. Spending is acknowledged only after both the checkpoint and deduplication row commit. Repeated IDs with matching payloads return the original acknowledgment across restart; changed payloads are rejected. A failed durable command insert rolls back the game and acknowledges no spending. Session credentials are hashed in storage and kept only in tab session storage on the client. Runtime databases and logs live under ignored .runtime. Health metadata identifies rules, map, protocol, SQLite and unfunded mode.

The service applies observe before transport and strips enemy routes, movement intent, focus IDs and inventory. Event endpoints are reduced to x and z, filtered by the receiving side current visibility, and historical events are not replayed to newly visible enemies. Payload assertions cover hidden coordinates and nested event data. Public station state and scores remain shared game information.

Client heartbeats every two seconds, stale connections pause the match after six seconds, and reconnect grace lasts 60 seconds. One absent participant forfeits after grace; both absent cause an abort without a winner. Restart loads verified checksummed checkpoints and waits for both authenticated clients before advancing. Version or checksum failures abort instead of inventing recovery. Checksums detect corruption, not hostile database modification. There is no security audit or production readiness claim.
