## Prepared deployment shape

Use a single Node 24 service with a durable SQLite volume, behind a TLS reverse proxy serving the frontend on the same origin. The frontend already uses /api for HTTP and WebSockets. The proxy strips /api. Do not point a static host at localhost or claim that a static upload deploys multiplayer.

deploy/Caddyfile is a prepared same origin configuration. Caddy supports WebSocket upgrades through reverse_proxy and automatic public HTTPS when DNS and ports are configured. Official references: https://caddyserver.com/docs/caddyfile/directives/reverse_proxy and https://caddyserver.com/docs/automatic-https . This configuration has not been exercised with public DNS or certificates. Caddy runtime verification remains pending. Docker CLI is installed, but docker info failed because the Linux engine pipe was unavailable; no image build was completed.

deploy/service.env.example lists public settings only. PUBLIC_OPERATION=true refuses startup without exact HTTPS ALLOWED_ORIGINS, an absolute DATABASE_PATH, PERSISTENT_STORAGE_CONFIRMED=true and TLS_TERMINATED=true. These declarations are operator assertions, not independent proof of a durable disk or working TLS. Configure and verify both before use. Keep Node loopback bound behind a same machine proxy. In a container network, expose Node only to the trusted proxy network. One process owns the database; do not start multiple replicas sharing this file.

/health includes application version, operator supplied BUILD_REVISION, rules, map, protocol, uptime and storage type. It does not expose file paths, private keys or sessions. public=false records that this source revision has no verified public deployment; publicOperation reports the selected configuration. HTTP health is not chain or match correctness proof.

SIGTERM and SIGINT close the application. WebSockets receive code 1001 and a restart reason; unresponsive sockets have a one second termination bound. Tick timers stop and the SQLite connection closes. A ten second process shutdown deadline remains as a last resort. Clients must reconnect after restart. Existing durable checkpoints, spending deduplication and connection grace rules remain in force.

## Secrets and funded mode

Windows local development retains separate DPAPI role files under ignored .runtime/testnet. Deployment and settlement keys are distinct. No secret is copied into the Docker context or frontend.

For a future Linux host, mount the dedicated settlement key as a read only file owned by the service user with mode 0400 or 0600. SETTLEMENT_KEY_FILE names that absolute path; it is not the key value. The adapter rejects invalid, oversized and group or world accessible files. Configure the hosting platform's secret storage to provide that file. Do not place it in the image, source, environment examples, browser or logs. TESTNET_DEPLOYMENT_FILE can name the read only public manifest generated by the real Gate 5 deployment. Immutable signer and code checks still apply. No deployment manifest exists yet. Hosted secret mounting has not been exercised.

deploy/Dockerfile is prepared source, not a built or published image. It uses the existing pinned npm lockfile and Node 24 base. Run from the repository root with docker build -f deploy/Dockerfile -t last-signal:local . when a Docker daemon is available. Mount the database directory with write access for uid 1000. Do not publish the raw Node port to the internet. Pin the base image digest after a real image build and verification, rather than inventing one here.

## Recovery and release drill

Before public use, stop accepting new matches, send SIGTERM, verify code 1001 and preserve the SQLite database plus its WAL and SHM files until the process has fully stopped. With the process stopped, make a private backup of the database and retain the exact source revision. Do not copy a live SQLite file alone. Backups contain sensitive authentication and signed match records; do not commit or publish them.

Restart against the same durable database. Reconnect both clients using their own saved credentials within the configured grace period. Verify the same room, sides, tick and budgets, and replay an already acknowledged paid command to confirm no duplicate spend. Verify an invalid or missing checkpoint aborts without an invented winner. Local tests cover these behaviors; a real public host restart remains an exit requirement.

For funded mode, separately interrupt RPC access and verify funded play pauses. Recheck canonical funding blocks before resuming. A reorganization must abort without a result authorization. If the server or signer cannot recover, retain public offer metadata and use contract deadlines to finalize refunds and claim through the wallet panel. Gate 4 receipts are local EVM evidence only. Gate 5 public receipts remain absent.

Release requires two genuinely external clients on the actual frontend and wss service, a completed authoritative match with one shared result, a host restart drill, verified durable storage, TLS and origin rejection, and real chain receipts only if funded mode is advertised. No security audit, penetration test, public load test or production readiness certification has been performed.
